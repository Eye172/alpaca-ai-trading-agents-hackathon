## TL;DR — решение в одном экране

**Что строим:** автономный агент, который ведёт не одну сделку, а **книгу опционов из двух рукавов**:

| Рукав | Что | Греки | Роль |
|---|---|---|---|
| **Core (carry)** | Defined-risk кредитные спреды / айрон кондоры на SPY, QQQ | long theta, short vega, short gamma | Зарабатывает каждый день, пока рынок спокоен |
| **Hedge (convexity)** | Малый долгий OTM-хвост | long gamma, long vega, short theta | Спасает от обвала, финансируется тетой Core |

**Killer feature:** перед каждым ордером агент строит **портфельную поверхность выплат** (все ноги + все открытые позиции, по сетке цен базового актива) и отказывает ордеру, если worst-case убыток книги выйдет за жёсткий бюджет. Это клиентская реализация **того же принципа, по которому маржу считает сам брокер** (universal spread rule: маржа = худший сценарий по совокупной выплате). Мы отказываем ордеру раньше, чем это сделает Alpaca.

**Почему так:** P&L за 5 торговых дней — это шум, его нельзя контролировать. Зато можно контролировать **вероятность** положительного P&L (short premium даёт ~75–85%) и полностью контролировать 4 из 5 критериев судейства. Стратегия «купить коллы по сигналу LLM» — это подбрасывание монеты минус спред минус тета.

**Стек:** Python + `alpaca-py` · **Alpaca MCP Server** (research-контур) + **Alpaca CLI** (autonomous-контур, оба, хотя требуется один) · Claude как reasoning-слой · Featherless AI как второй, независимый модельный голос (+ право на партнёрский приз) · SQLite для состояния и аудита · дашборд на Vercel.

**Ожидаемый результат:** +0.3…+1.5% за неделю, P(положительный) ≈ 75–85%, реалистичный худший случай −3…−5%, убыток больше 5% отсечён жёстким гейтом.

# ЧАСТЬ 1. Как устроена Alpaca — ресерч

## 1.1. Что такое Alpaca

Alpaca — это **программируемый брокер**. Не терминал с кнопками, а брокерская инфраструктура, к которой обращаются по API. Юридически:

- **Alpaca Securities LLC** (dba «Alpaca Clearing») — брокер-дилер, член FINRA/SIPC, дочка **AlpacaDB, Inc.**
- **Alpaca Crypto LLC** — крипта, зарегистрирована в FinCEN как MSB (NMLS # 2160858), **не** член SIPC/FINRA
- **AlpacaDB, Inc.** — технология и сервисы

Три продуктовые линии:

| Продукт | Для кого | Что даёт |
|---|---|---|
| **Trading API** | Алго-трейдеры, ретейл, хедж-фонды, проп-фирмы | Торговля со своего счёта: акции, ETF, опционы, крипта |
| **Broker API** | Финтех-компании, институты | Полный end-to-end брокеридж: онбординг, KYC, счета клиентов, торговля от их имени |
| **Market Data API** | Все | Реалтайм и историчка: акции, крипта, опционы, индексы, новости, корпдействия |

**Нам нужен Trading API + Market Data API.** Broker API — не для этого хакатона.

## 1.2. Архитектурная модель

```
                    ┌──────────────────────────────┐
   твой код ───────▶│      Trading API             │──▶ ордера, позиции, счёт
                    │  paper-api.alpaca.markets    │
                    │  api.alpaca.markets (live)   │
                    └──────────────────────────────┘
                    ┌──────────────────────────────┐
   твой код ───────▶│    Market Data API           │──▶ бары, котировки, чейн, греки
                    │  data.alpaca.markets         │
                    └──────────────────────────────┘
                    ┌──────────────────────────────┐
   твой код ───────▶│    WebSocket streams         │──▶ realtime trades/quotes
                    │  stream.data.alpaca.markets  │
                    └──────────────────────────────┘
```

Точка входа определяется **base URL**. Бумажный и живой контуры — это **разные хосты и разные ключи**. Ключ от бумажного счёта физически не может отправить живой ордер. Это наша главная гарантия безопасности.

Поверх REST существуют четыре официальных клиента:

1. **SDK** — `alpaca-py` (Python), `alpaca-trade-api-js` (JS/TS)
2. **CLI** — `alpaca`, бинарник на Go
3. **MCP Server** — `alpaca-mcp-server`, 65 инструментов для AI-ассистентов
4. **Skills** — `alpacahq/alpaca-skills`, 13 `SKILL.md` файлов с инструкциями для агентов

## 1.3. Paper trading — как оно реально работает

Это критично понимать, потому что **весь наш P&L живёт здесь**.

**Создание счёта.** Paper-only аккаунт открывается по одному email, глобально, без верификации. По умолчанию — **$100,000**. Можно держать **несколько бумажных счетов** (в дашборде: клик по номеру счёта → «Open New Paper Account»).

> ⚠️ **Баланс фиксируется в момент создания и не меняется.** Чтобы получить другой стартовый капитал — создаётся новый счёт. Требование хакатона ($100,000) совпадает с дефолтом, но проверить обязательно.

**Endpoint:** `https://paper-api.alpaca.markets`

**Как симулируются исполнения:**

- Ордер исполняется только когда он **marketable**: buy limit — когда цена ≤ лучшего ask; sell limit — когда ≥ лучшего bid
- **Количество НЕ проверяется против объёмов NBBO.** Можно получить филл больше реальной ликвидности
- В ~10% случаев применяется **случайный частичный филл**
- Котировки берутся реальные, рыночные

**Чего paper НЕ симулирует:**

| Не симулируется | Последствие для нас |
|---|---|
| Рыночное воздействие (market impact) | Наш P&L оптимистичнее реального |
| Проскальзывание от задержки | То же |
| Позиция в очереди заявок | Лимитники исполняются «идеально» |
| Комиссии за заём бумаг | Не важно, мы не шортим акции |
| Дивиденды | SPY идёт экс-див ~19 сентября — вне нашего окна ✅ |
| Регуляторные сборы | Незначительно |

**Что работает так же, как в живом:** маржа, шорт, пре/пост-маркет для акций.

**Опционы в paper:** включены **по умолчанию**, ничего запрашивать не надо.

> ⚠️ Внеторговые события (экзерсайз, ассигнация, экспирация) **синхронизируются в начале следующего дня**, хотя позиции обновляются мгновенно. Значит любая экспирация внутри нашего окна = сутки неопределённости в P&L прямо перед судейством. **Мы этого не допустим вообще.**

## 1.4. Опционы на Alpaca — полный разбор

### Уровни допуска

| Уровень | Что разрешено |
|---|---|
| **0** | Опционы выключены |
| **1** | Продажа покрытых коллов, продажа обеспеченных путов |
| **2** | Всё из L1 + покупка коллов, покупка путов |
| **3** | Всё из L1–L2 + **вертикальные спреды и мультиноговые стратегии** |

> ✅ **Все бумажные счета автоматически получают Level 3.** Заявка нужна только для живой торговли. Значит нам сразу доступны айрон кондоры, страддлы, стрэнглы, бабочки, все спреды — без единого запроса на апрув.

### Символика контрактов

Формат: `{ROOT}{YYMMDD}{C|P}{STRIKE×1000, 8 цифр}`

```
SPY260918C00650000
│   │      │ │
│   │      │ └── страйк 650.000
│   │      └──── Call
│   └─────────── экспирация 18 сентября 2026
└─────────────── базовый актив SPY
```

### Типы ордеров и ограничения

| Параметр | Одна нога | Мультинога (mleg) |
|---|---|---|
| Типы ордера | `market`, `limit`, `stop`, `stop_limit` | **только `market` и `limit`** |
| Time in force | `day`, `gtc` | `day`, `gtc` |
| Extended hours | **запрещено** | запрещено |
| Дробные / notional | **запрещено** | запрещено |
| Количество | только целое | только целое |
| Стиль | American | American |

### Мультиноговые ордера (mleg)

```jsonc
{
  "order_class": "mleg",
  "qty": "1",
  "type": "limit",
  "limit_price": "1.20",        // цена всей конструкции, нетто
  "time_in_force": "day",
  "legs": [
    { "symbol": "SPY260918P00620000", "side": "sell",
      "ratio_qty": "1", "position_intent": "sell_to_open" },
    { "symbol": "SPY260918P00610000", "side": "buy",
      "ratio_qty": "1", "position_intent": "buy_to_open"  }
  ]
}
```

Правила:

- **От 2 до 4 ног.** Не больше четырёх
- `ratio_qty` в **несократимом виде** — НОД всех соотношений должен быть равен 1. `2:4` отклонят, нужно `1:2`
- `position_intent`: `buy_to_open` / `sell_to_open` / `buy_to_close` / `sell_to_close`
- **Нельзя** смешивать акции и опционы в одном mleg
- **Нельзя** непокрытые короткие ноги внутри mleg
- Один mleg-ордер может **одновременно закрыть старую конструкцию и открыть новую** (роллинг в 4 ноги)

### Маржа: universal spread rule

Alpaca считает поддерживающую маржу **не суммой требований по отдельным спредам**, а как **худший сценарий по совокупной выплате всего портфеля** на сетке цен базового актива.

```
cost_basis = maintenance_margin + (net_option_premiums × 100)
```

> 🔑 **Это и есть точка входа для нашей killer feature.** Мы реализуем ровно этот же принцип на своей стороне и запрещаем ордер до его отправки. Судьи из Alpaca увидят, что мы поняли их маржинальный движок.

### Экспирация, экзерсайз, ассигнация

С **15:30 ET в день экспирации**:

- новые позиции по этому контракту не открываются
- ITM-позиции (в деньгах хотя бы на $0.01) оцениваются
- длинные коллы/путы при достаточной покупательной способности — **авто-экзерсайз**; если BP не хватает — **ликвидация позиции за час до экспирации**
- покрытые коллы и обеспеченные путы в ITM — **авто-ассигнация**
- OTM — истекают бесполезными

Активности: `OPEXC` (экзерсайз), `OPASN` (ассигнация), `OPEXP` (экспирация), `OPTRD` (получившаяся сделка по акции).

Экзерсайз вручную: `POST /v2/positions/{symbol_or_contract_id}/exercise`.

> ⚠️ **Уведомления об ассигнации не приходят по WebSocket.** Надо опрашивать REST-эндпоинт активностей.

## 1.5. Рыночные данные — что даёт бесплатный план

Это второе критичное ограничение.

| | **Basic (бесплатно)** | **Algo Trader Plus ($99/мес)** |
|---|---|---|
| Акции реалтайм | только **IEX** | все биржи США (SIP) |
| **Опционы** | **Indicative Pricing Feed** | **OPRA** |
| WebSocket | 30 символов / 200 опционных котировок | безлимит / 1000 котировок |
| Историчка | с 2016, но **последние 15 минут закрыты** | полный доступ |
| **Rate limit** | **200 запросов/мин** | 10 000/мин |

**Indicative feed** — бесплатная производная от OPRA: котировки **индикативные** (не настоящие рыночные), сделки **задержаны на 15 минут**. Историчка по опционам — только с февраля 2024.

### ✅ Ключевая находка: греки бесплатны

Эндпоинты `option chain` и `option snapshots` возвращают **greeks (delta, gamma, theta, vega, rho по Блэку-Шоулзу) и impliedVolatility — независимо от фида.**

```
GET /v1beta1/options/snapshots/{underlying}      # весь чейн
GET /v1beta1/options/snapshots?symbols=...       # до 100 контрактов
```

Параметры чейна: `feed`, `type` (call/put), `strike_price_gte/lte`, `expiration_date[_gte/_lte]`, `root_symbol`, `updated_since`, `limit` (1–1000), `page_token`.

**Вывод: Algo Trader Plus нам не нужен.** Дельты для выбора страйков, IV для оценки премии, поверхность греков для риск-модели — всё доступно на бесплатном тарифе. Это снимает главный предполагаемый барьер.

> ⚠️ Но помним: котировки индикативные. Значит **mark-to-market нашего портфеля слегка неточен**, и лимитники надо ставить с запасом. Об этом — в разделе рисков.

**200 запросов/мин** — это ~3 запроса в секунду. Один вызов чейна возвращает до 1000 контрактов, так что при разумной архитектуре лимит не мешает. Но наивный цикл «по контракту на запрос» упрётся мгновенно.

# ЧАСТЬ 2. Реальные рамки задачи

## 2.1. Сколько у нас на самом деле торгового времени

| Дата | День | Рынок | Доступно |
|---|---|---|---|
| 28 авг | Пт | 09:30–16:00 ET | **~5 ч** (старт хакатона 11:00 ET) |
| 29–30 авг | Сб–Вс | закрыт | — |
| 31 авг | Пн | 09:30–16:00 ET | полный день |
| 1 сен | Вт | 09:30–16:00 ET | полный день |
| 2 сен | Ср | 09:30–16:00 ET | полный день |
| 3 сен | Чт | 09:30–16:00 ET | полный день |
| 4 сен | Пт | 09:30–**11:00 ET** | **~1.5 ч** до дедлайна |

**Итого ≈ 4.9 торговых дня.** Праздников внутри окна нет (Labor Day — 7 сентября, уже после).

## 2.2. Почему P&L — это шум, и что с этим делать

Дневное стандартное отклонение SPY ≈ 0.8–1.0%. За 5 дней σ ≈ 2%. Любая направленная ставка на этом горизонте — монетка.

Три следствия:

1. **Нельзя планировать «занять первое место по P&L».** Можно планировать **вероятность** оказаться в плюсе.
2. **Максимизируем P(P&L > 0), а не E[P&L].** Стратегия с +0.8% при 80% вероятности лучше для рейтинга, чем +15%/−15% при 50%.
3. **Остальные 4 критерия детерминированы.** Их мы контролируем на 100%. Туда идёт основное усилие.

## 2.3. Главный враг — бид-аск спред

В paper рыночный ордер покупает по ask и продаёт по bid. Полный оборот = полный спред.

| Инструмент | Типичный спред | Round trip |
|---|---|---|
| SPY ATM опцион | $0.01–0.02 при цене $5 | **0.2–0.4%** |
| QQQ ATM | $0.02–0.05 при $6 | 0.3–0.8% |
| Средняя акция, OTM | $0.10–0.30 при $1.50 | **7–20%** ☠️ |

**Вывод, определяющий всю стратегию:** торгуем **только SPY, QQQ, IWM** — самые узкие спреды на планете, — и **минимизируем число оборотов**. Агент, который «активно торгует» 50 раз за неделю на неликвиде, гарантированно уйдёт в минус только на спреде.

## 2.4. Что судьи реально увидят

По ID бумажного счёта у них есть:

- `GET /v2/account` — equity, buying power
- `GET /v2/account/portfolio/history` — **кривая эквити** ← главное, что они посмотрят
- `GET /v2/account/activities` — каждый филл

Ордеров должно быть достаточно, чтобы это читалось как «агент работал» (~8–15 конструкций за неделю), но не сотни.

# ЧАСТЬ 3. Разбор всех путей решения

## 3.1. Стратегии

### A. Long premium — покупка коллов/путов/страддлов/стрэнглов

**Механика:** платим премию, получаем неограниченный апсайд, ограниченный даунсайд.

- ✅ Убыток ограничен премией **по конструкции**, маржа не нужна, риска ассигнации нет
- ✅ Просто реализовать
- ❌ **Отрицательное матожидание.** Implied volatility в среднем выше realized (это и есть премия за риск волатильности) — покупатель премии платит за страховку
- ❌ Тета съедает позицию каждый день. За 5 дней при 21 DTE уходит ~25% временной стоимости
- ❌ P(положительный P&L) ≈ 35–40%
- ❌ **Занято.** Vega сдала ровно это в первый день, с опубликованной моделью

**Вердикт:** ставка на удачу с отрицательным EV. Отклонено как основа.

### B. Short premium, defined risk — кредитные спреды, айрон кондоры

**Механика:** продаём OTM-спред, получаем кредит, максимальный убыток = ширина спреда − кредит, известен в момент входа.

- ✅ **Положительное матожидание** — забираем ту самую премию за риск волатильности
- ✅ Тета работает **на нас**
- ✅ P(положительный P&L) за 5 дней при коротких страйках на ~15–20 дельте ≈ **80–88%**
- ✅ Level 3 в paper даёт кондоры нативно, одним mleg-ордером
- ✅ Риск определён и по конструкции, и на уровне брокерской маржи
- ⚠️ Хвостовой риск: резкий обвал бьёт по всем коротким путам сразу
- ⚠️ Выглядит как «продал вол и молюсь», если нет решающего слоя

**Вердикт:** лучший P&L-движок. Хвост закрываем рукавом Hedge.

### C. Дельта-нейтральный маркет-мейкинг

- ❌ Paper не моделирует очередь заявок — котировать бессмысленно, филлы нереалистичны
- ❌ Rate limit 200/мин убивает частоту

**Вердикт:** невозможно на этой инфраструктуре. Отклонено.

### D. Covered calls / wheel

- ✅ Положительная тета, Level 1
- ❌ 100 акций SPY ≈ $65k из $100k — капитал заперт
- ❌ **P&L определяется движением акции, а не опционом.** Это ставка на SPY с косметикой
- ❌ Слабо по критерию «стратегия обязана включать опционы» — формально да, содержательно нет

**Вердикт:** слишком медленно и не про опционы. Отклонено.

### E. Event-driven / earnings

- ❌ 28 авг — 4 сен: провал между сезонами отчётности. Крупных отчётов почти нет
- ❌ Отчёты второго эшелона = широкие спреды = см. 2.3

**Вердикт:** нет топлива в окне. Отклонено.

**Вердикт:** самый популярный и самый плохой путь. Отклонено как основа. Новостной сигнал используем только как **вето-фильтр**, а не как генератор сделок.

## 3.2. Архитектуры принятия решений

### A1. Один LLM-агент с инструментами

Модель в цикле, ходит инструментами MCP, сама решает.

- ✅ Быстро, «честно автономно»
- ❌ Недетерминированно: одинаковый вход → разные сделки
- ❌ LLM плохо считает риск арифметически — а именно это здесь критично
- ❌ Нечего показать как «инженерию»

### A2. Чисто детерминированный бот, LLM только для отчётов

- ✅ Предсказуемо, надёжно
- ❌ **Провал по требованию «AI-агент».** Это обычный алго-бот с LLM-обёрткой

### A3. Мультиагентная система с детерминированным риск-слоем ✅

LLM-агенты предлагают и спорят, **риск считает чистый Python**. Ровно этот шаблон — в официальном туториале Alpaca «Multi-Agent AI Trading System» (Risk Guard там — детерминированная функция, без LLM).

- ✅ Автономно и объяснимо
- ✅ Риск-гейты нельзя «уговорить» промптом
- ✅ Совпадает с рекомендацией самого вендора — судьи из Alpaca это узнают
- ✅ Есть что показывать в архитектуре

**Выбрано: A3.**

> В туториале Alpaca есть **Human Gate** — ручное подтверждение. У нас его быть не может (требуется автономность), поэтому его роль берут на себя **два независимых модельных голоса + детерминированный симулятор портфеля**. Это осознанная замена, и её надо явно объяснить в write-up — судьи знают свой же туториал.

## 3.3. Что уже сдал конкурент (Vega)

Единственный сабмит на момент написания, сдан в день старта:

- Long-gamma стрэнглы OTM на SPY, экспирация **строго после закрытия конкурса**
- Уменьшает размер при дорогой IV против 20-дневной реализованной
- Отказ от контракта без двусторонней котировки или со спредом > 25% от mid
- Восстанавливает IV инверсией Блэка-Шоулза и **сверяет с греками брокера**
- Сознательно без стоп-лоссов, с опубликованной ценой этого решения (стоп срабатывает на 91.0% путей, роняет их же вероятность top-3 с 15.9% до 6.2%)
- **48 из 48 утверждений воспроизводятся одной командой без ключей**
- Прямо пишут: *«The strategy is not the interesting part»*

**Чему учимся:**

1. Экспирация после дедлайна — правильно, копируем
2. Гейты ликвидности — правильно, копируем и ужесточаем
3. **Воспроизводимость — их главное оружие.** Нужен свой ответ, не хуже
4. Их слабое место — **отрицательный EV самой стратегии**. Они честно это признают. Мы строим ровно противоположную сторону сделки: они покупают выпуклость, мы её продаём и хеджируем остаток

**Наше позиционирование против них:** у них — один тип позиции с отрицательным EV и упор на честность. У нас — **книга из двух рукавов с положительным carry и хеджированным хвостом**, портфельный риск-движок и та же планка воспроизводимости. Это шаг вперёд, а не повтор.

# ЧАСТЬ 4. Выбранное решение

## 4.1. Концепция

> **Автономный опционный «деск», который ведёт книгу, а не совершает сделки.**

Агент не отвечает на вопрос «куда пойдёт рынок». Он отвечает на два других:

1. **Достаточно ли дорога сейчас волатильность, чтобы её продавать?** (IV против реализованной)
2. **Выдержит ли книга худший сценарий, если я добавлю эту позицию?** (портфельная поверхность выплат)

Направление рынка не прогнозируется вообще. Это и есть содержательная оригинальность: **все остальные предсказывают цену, мы торгуем премию за риск.**

**Рабочее название: `THETA DESK`** (альтернативы: `CARRY`, `DELTA ZERO`, `VOLBOOK`).

## 4.2. Два рукава книги

```
                 THETA DESK — книга
   ┌────────────────────────────┬───────────────────────────┐
   │  CORE (carry)              │  HEDGE (convexity)        │
   │  ~85% риск-бюджета         │  ~15% риск-бюджета        │
   ├────────────────────────────┼───────────────────────────┤
   │  Put credit spreads        │  Дальние OTM путы         │
   │  Iron condors              │  или put backspread       │
   │  SPY / QQQ, 21 DTE         │  SPY, 21–35 DTE           │
   ├────────────────────────────┼───────────────────────────┤
   │  +theta  −vega  −gamma     │  −theta  +vega  +gamma    │
   ├────────────────────────────┼───────────────────────────┤
   │  Зарабатывает в штиль      │  Платит в обвал           │
   │  Умирает в обвал           │  Финансируется тетой Core │
   └────────────────────────────┴───────────────────────────┘
             ↓                            ↓
        нетто: long theta, но с выпуклым хвостом
```

**Почему это сильнее одного рукава:**

- Голый short premium убивает один плохой день. Hedge это закрывает
- Голый long premium медленно истекает тетой. Core её оплачивает
- Появляется **настоящая работа для риск-движка**: он балансирует два противоположных набора греков, а не проверяет одну сделку
- В презентации это читается как **портфельный менеджмент**, а не как «бот с сигналом»

## 4.4. Killer feature подробно

```python
def portfolio_worst_case(book_legs, candidate_legs, spot, horizon_days, iv_surface):
    """
    Возвращает худший P&L книги при добавлении кандидата.
    Сетка цен базового актива ±20% с шагом 0.5%.
    Каждая нога переоценивается по Блэку-Шоулзу на горизонт судейства.
    """
    worst = 0.0
    for s in price_grid(spot, lo=0.80, hi=1.20, step=0.005):
        pnl = 0.0
        for leg in book_legs + candidate_legs:
            v = bs_price(s, leg.strike, horizon_days, iv_surface[leg.symbol],
                         leg.right, r=RF_RATE)
            pnl += leg.sign * (v * 100 * leg.qty) - leg.cost_basis
        worst = min(worst, pnl)
    return worst
```

**Почему это выигрывает у судей:**

1. Это **портфельный** риск, а не «стоп по позиции». Все остальные проверят одну сделку — мы проверяем книгу целиком
2. Это **тот же принцип**, по которому Alpaca считает маржу. Прямая отсылка к их документации
3. Он **действительно нужен** — у нас два рукава с противоположными греками, и только совместная переоценка показывает реальный риск
4. Он **отказывает** — и мы публикуем счётчик отказов. Агент, который умеет не торговать, выглядит взрослее любого, который торгует всегда
5. Он **проверяемый** — сетка и формула детерминированы, любой может пересчитать

| Core: число конструкций | 3–5 одновременно | Диверсификация по страйкам и датам входа |
| Hedge: страйк | дельта ~0.05, put | Дёшево, платит только в настоящем обвале |
| Hedge: бюджет | ≤ 0.6% эквити суммарной премии | Оплачивается тетой Core |
| Целевой кредит Core | ≥ 25% от ширины спреда | Иначе риск-вознаграждение не окупает спред |
| Темп | 1–3 конструкции в день | ~10–14 за неделю = видимая активность без переторговки |

**Явное решение, которое надо задокументировать:** книга **не выравнивается перед дедлайном**. Закрытие 8–10 конструкций рыночными ордерами в последнее утро стоит ~0.3–0.5% эквити на спреде. Позиции остаются с оценкой по рынку. Мы публикуем эту цену — по образцу того, как Vega опубликовала цену своего решения не ставить стопы. Это ровно тот тип честности, который здесь вознаграждают.

## 4.7. Как решение закрывает все 5 критериев

| Критерий | Чем закрываем |
|---|---|
| **P&L Performance** | Положительный EV (премия за риск волатильности), P(плюс) 80–88%, гладкая кривая эквити, ~10–14 конструкций = видимая активность |
| **Technology Implementation** | **MCP + CLI одновременно** (требуется один), mleg-ордера, греки и IV из чейна, portfolio history, activities, clock/calendar, идемпотентность через `client_order_id`, `--dry-run`, alpaca-skills |
| **Creativity & Originality** | Никто не предсказывает цену — торгуем премию за риск; книга из двух рукавов; **портфельный симулятор выплат как право вето**; два независимых модельных голоса с расхождением как сигналом размера |
| **Presentation & Execution** | Живой дашборд с поверхностью выплат и журналом решений; видео показывает реальные сделки; каждое число в сабмите пересчитывается одной командой |
| **Social Engagement** | 5 постов: архитектура → killer feature → первая отказанная сделка → кривая эквити → итог с числами |

### Выбор страйка по дельте

```python
def pick_short_strike(chain: dict, right: str, target_delta: float = 0.17):
    best, best_err = None, 1e9
    for sym, s in chain.items():
        g = s.get("greeks") or {}
        d = g.get("delta")
        if d is None:
            continue
        if right == "put" and d >= 0:
            continue
        err = abs(abs(d) - target_delta)
        if err < best_err:
            best, best_err = sym, err
    return best
```

### Гейт ликвидности

```python
MAX_REL_SPREAD = 0.08

def liquid(snapshot: dict) -> tuple[bool, str]:
    q = snapshot.get("latestQuote") or {}
    bid, ask = q.get("bp", 0), q.get("ap", 0)
    if bid <= 0 or ask <= 0:
        return False, "no two-sided quote"
    mid = (bid + ask) / 2
    if (ask - bid) / mid > MAX_REL_SPREAD:
        return False, f"spread {(ask-bid)/mid:.1%} > {MAX_REL_SPREAD:.0%}"
    return True, "ok"
```

### Отправка mleg через CLI

```python
# src/exec/cli_bridge.py
import json, subprocess, hashlib

def client_order_id(strategy: str, legs: list, day: str) -> str:
    key = f"{day}|{strategy}|" + "|".join(sorted(l["symbol"] for l in legs))
    return hashlib.sha256(key.encode()).hexdigest()[:32]

def submit_mleg(legs: list, limit_price: float, qty: int, day: str) -> dict:
    payload = {
        "order_class": "mleg",
        "qty": str(qty),
        "type": "limit",
        "limit_price": f"{limit_price:.2f}",
        "time_in_force": "day",
        "client_order_id": client_order_id("core", legs, day),
        "legs": legs,
    }
    p = subprocess.run(
        ["alpaca", "api", "POST", "/v2/orders"],
        input=json.dumps(payload), capture_output=True, text=True,
    )
    if p.returncode != 0:                    # 0 ok · 1 api error · 2 auth
        raise RuntimeError(f"exit={p.returncode} stderr={p.stderr}")
    return json.loads(p.stdout)
```

## 7.2. Структура write-up (одна страница)

Требование хакатона: **AI logic · risk gates · Alpaca infrastructure**. Ровно три блока, в этом порядке.

**1. AI logic.** Агент не прогнозирует цену. Он оценивает премию за риск волатильности (IV из чейна против 20-дневной реализованной) двумя независимыми моделями — Claude и открытой моделью через Featherless. Расхождение голосов не блокирует сделку, а вдвое сокращает размер. Выбор конструкции и страйков по дельте — детерминированный, LLM в нём не участвует.

**2. Risk gates.** 16 гейтов, все — чистый Python, LLM не может их обойти. Центральный: портфельный симулятор выплат. Перед каждым ордером книга целиком переоценивается по сетке цен базового актива ±20% на горизонт судейства; если худший P&L выходит за 5% эквити — ордер не отправляется. Это клиентская реализация того же принципа, по которому Alpaca считает маржу (universal spread rule). За неделю гейт отклонил N ордеров.

**3. Alpaca infrastructure.** Trading API — исполнение. Market Data API — чейн с греками и IV (бесплатный indicative-фид, подписка не потребовалась). MCP Server — исследовательский контур. CLI — автономный контур: идемпотентность через client_order_id, exit codes, `--dry-run`. Мультиноговые ордера — `order_class: mleg`, 2–4 ноги, `ratio_qty` в несократимом виде. Экспирация всегда строго после закрытия конкурса: ноль ассигнаций и экспираций внутри окна судейства.

| Судьи хотели больше сделок | Средняя | Средний | 10–14 конструкций + управление позициями = видимая активность; логика темпа объяснена в write-up |
